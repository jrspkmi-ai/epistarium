# Migrate from v0.6.0 to v0.7.0

This is a release-preparation update. The ten persona slugs, CLI commands, evidence statuses, schema keys, and F1 to F4 handoffs remain.
Canonical .agents/skills paths are unchanged. English and Indonesian continue to use one implementation.
Original work now has an MIT notice. PyMuPDF remains separately licensed and the public release gate is HOLD.

<!-- section: steps -->
## Migration steps

1. Back up private inputs, configurations, and outputs outside the old project.
2. Extract the candidate into a separate directory. Keep the full folder tree.
3. Create a fresh venv. Install the candidate using your OS guide.
4. Run doctor and confirm version 0.7.0 and ten skills at the project root.
5. Run First Research with fresh output folders. Keep synthetic examples separate from empirical work.
6. Review source rights before reusing any legacy live-data configuration.
7. Generate a Claude adapter only if needed. Rerun --apply after canonical skill changes.
8. Check licensing and readiness before requesting publication.

The PDF bound is now >=1.28.2,<2. Do not downgrade a mixed 2.x environment in place.
The public numeric BPS example no longer asserts confirmed rights by default. Set rights only after checking your permitted use.
No existing user output is migrated or overwritten automatically.

Rerun Domares and Synthia for old records whose printed_page contains the literal string printed_page.
Preserve old artifacts for traceability. Do not silently edit their audit hashes.
ORIGO v1.0.0 identifies its mapping protocol. The EPISTARIUM package version remains 0.7.0.
